# Story: CLM Real-time Notifications & WebSockets [Implemented ✅]

## 1. 개요 (Overview)
- **목표:** 비동기적으로 처리되는 장기 작업(LLM AI 분석, 외부 API 백그라운드 웹훅)의 상태 변화나 시스템 주요 이벤트를 클라이언트 측에 즉각적으로 알려주는 실시간 알림 시스템(WebSockets)을 구축한다.

## 2. 페르소나 (Persona)
- **Tenant User:** 장시간 소요되는 AI 분석을 요청한 후, 페이지를 새로고침 하지 않고도 분석 완료 시 즉시 브라우저 우측 하단의 알림 팝업을 통해 결과를 인지하고 싶어 한다.

## 3. 인수 조건 (Acceptance Criteria)

### 시나리오 1: 웹소켓 연결 및 테넌트/유저 룸 구독 [Done ✅]
- [x] **Given** 사용자가 클라이언트 대시보드에 로그인한 상태이다.
- [x] **When** 프론트엔드 앱이 로드되면
- [x] **Then** JWT 토큰 기반 인증을 거쳐 백엔드 Socket.io 게이트웨이와 보안 웹소켓 연결을 수립한다.
- [x] **And** 시스템은 해당 사용자를 식별하여 자신의 `tenant_id` 및 `user_id` 방(Room)에 자동으로 조인시킨다.

### 시나리오 2: 백엔드 이벤트 발행과 푸시 알림 [Done ✅]
- [x] **Given** AI 계약 분석이 성공적으로 종료되거나 서비스 단에서 알림 이벤트가 발생한다.
- [x] **When** NotificationService 구역에서 `NotificationChannel.emit()` 기능을 수행하면
- [x] **Then** 대상 테넌트/유저의 웹소켓 룸으로 메시지가 푸시된다.
- [x] **And** 프론트엔드의 리스너가 이를 수신하고, 토스트(Toast) 형태의 실시간 UI 알림을 띄운다.

## 4. 아키텍처 및 제약사항 노트 (Architecture Notes)
- **기술 스택:** `@nestjs/websockets`, `@nestjs/platform-socket.io`, 클라이언트 단 `socket.io-client`.
- **보안 가드 연동:** `WsGuard` 구현 시 기존 HTTP AuthGuard(JWT 검증 로직)의 메커니즘을 동일하게 차용하여 허가받지 않은 소켓 연결 차단.
- **복원력:** 네트워크 단절 시 Socket.io 내장 재연결 로직 사용 및, 중요한 알림 유실에 대비한 DB Polling fallback(점진적 도입 고려).
