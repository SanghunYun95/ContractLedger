# Story: CLM LLM Enhanced Contract Analysis [Implemented ✅]

## 1. 개요 (Overview)
- **목표:** 업로드된 계약서(PDF 등)를 실제 오픈AI(OpenAI) LLM과 연동하여 텍스트를 분석하고, 핵심 리스크 요인을 추출하며, 신뢰도 높은 리스크 점수를 산출하는 고도화된 AI 파이프라인을 구축한다.

## 2. 페르소나 (Persona)
- **Legal Reviewer / Tenant Administrator:** 시스템에 업로드된 계약서의 독소 조항이나 핵심 쟁점을 AI를 통해 빠르고 정확히 파악하여 법무 검토 시간을 단축하고자 한다.

## 3. 인수 조건 (Acceptance Criteria)

### 시나리오 1: 비동기 방식의 LLM 분석 파이프라인 실행 [Done ✅]
- [x] **Given** 사용자가 대시보드에서 계약서 분석(AI Review) 액션을 트리거한다.
- [x] **When** 백엔드의 `analyze` 서비스가 호출되면
- [x] **Then** 시스템은 대기 상태(약 2초의 하드코딩된 setTimeout) 대신, 실제 OpenAI API를 비동기적으로 호출하여 계약서 텍스트의 분석을 시작한다.
- [x] **And** 응답 대기 중 프론트엔드는 사용자에게 "분석 중" 상태를 적절히 표시한다.

### 시나리오 2: 리스크 스코어링 및 구조화된 결과 도출 [Done ✅]
- [x] **Given** OpenAI API가 응답을 반환한다.
- [x] **When** 응답 데이터를 파싱할 때
- [x] **Then** 프롬프트 엔지니어링을 통해 도출된 [Risk Score (0~100)], [Risk Level (Low/Medium/High)], [독소 조항 요약], [발견된 핵심 키워드] 항목을 `Contract` 엔티티의 `riskScore` 및 `riskAnalysis` JSON 필드에 알맞게 매핑한다.
- [x] **And** 분석 실패나 타임아웃 발생 시, 우아한 에러 처리(Graceful degradation)를 통해 사용자에게 실패를 알린다.

### 시나리오 3: 감사 로그 연동 [Done ✅]
- [x] **When** 성공적으로 분석이 완료되고 데이터베이스 업데이트가 끝나면
- [x] **Then** `audit.log.created` 이벤트를 발생시켜 `CONTRACT_AI_REVIEW` 액션과 부여된 리스크 점수를 시스템 로그에 기록한다.

## 4. 아키텍처 및 제약사항 노트 (Architecture Notes)
- **의존성:** `@nestjs/axios` 또는 `openai` 공식 Node.js SDK 구성.
- **주요 환경 변수:** `OPENAI_API_KEY`, `OPENAI_MODEL` (예: gpt-4o-mini 또는 gpt-3.5-turbo) 설정 필수.
- **프롬프트 디자인:** 시스템 프롬프트를 통해 반드시 JSON 형식의 정형 데이터를 반환하도록 강제(`response_format: { type: "json_object" }`).
- **확장성:** 텍스트 추출(PDF parsing)은 향후 OCR 처리로 확장될 수 있도록 모듈화.
