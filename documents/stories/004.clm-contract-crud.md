# Story: Contract Management CRUD [Implemented ✅]

## 1. 개요 (Overview)
- **목표:** 멀티 테넌트 환경에서 안전하게 계약서 데이터를 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)하는 핵심 도메인 기능을 구현한다.

## 2. 인수 조건 (Acceptance Criteria)

### 시나리오 1: 테넌트 격리가 보장된 생성 [Done ✅]
- [x] **Given** 유저는 자신의 테넌트에 속해 있다.
- [x] **When** 계약 정보를 입력하여 생성을 요청하면
- [x] **Then** 해당 계약 데이터는 유저의 `tenant_id`와 함께 저장되어야 한다.
- [x] **And** 성공 시 `audit.log.created` 이벤트가 발행되어 감사 로그에 기록되어야 한다.

### 시나리오 2: 교차 테넌트 접근 방지 (Security) [Done ✅]
- [x] **Given** 유저 A(Tenant A)가 유저 B(Tenant B)의 계약 ID로 조회를 요청한다.
- [x] **When** 백엔드가 요청을 처리할 때
- [x] **Then** 데이터가 존재하더라도 요청자의 `tenant_id`와 불일치하면 `404 Not Found` 또는 `403 Forbidden`을 반환한다.

## 3. 아키텍처 및 제약사항 (Architecture Notes)
- **엔티티:** `Contract` (id, title, status, tenantId, createdBy, createdAt)
- **격리:** 모든 Query에 `tenantId` 필터링 강제 적용.
