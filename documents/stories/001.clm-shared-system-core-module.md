# Story: CLM Shared System Core Module [Implemented ✅]

## 1. 개요 (Overview)
- **목표:** AI 기반 계약 생애주기 관리(CLM) 플랫폼을 위한 공통 시스템(Shared System) 백엔드 코어 모듈을 구현하여 멀티 테넌트 격리(Isolation), 이벤트 기반 감사 로그 적재, 외부 AI 서비스 연동 웹훅을 지원한다.

## 2. 페르소나 (Persona)
- **Tenant Administrator (테넌트 최고 관리자):** 자신이 소속된 테넌트의 모든 활동 기록을 확인하고 보안을 관리하고자 한다.
- **System Administrator (사내 시스템 관리자):** 시스템 상의 모든 알림과 외부 통합 기능을 관리 및 모니터링한다.
- **External AI Agent (외부 AI 에이전트):** 특정 계약 상태(예: 만료 도래, 리소스 파악)를 플랫폼에 통보하여 알림을 유발한다.

## 3. 인수 조건 (Acceptance Criteria)

### 시나리오 1: 멀티 테넌트 인가 가드 (Multi-Tenant AuthZ Guard) [Done ✅]
- [x] **Given** 사용자가 API 요청을 보낼 때 `x-tenant-id` 헤더와 유효한 `Authorization` 토큰을 포함한다.
- [x] **When** API 컨트롤러에 접근하기 전 
- [x] **Then** 시스템은 전역 가드를 통해 해당 유저가 `x-tenant-id`에 속한 유효한 사용자인지 검증한다.
- [x] **And** 유효하지 않거나 테넌트가 불일치할 경우 `403 Forbidden` 커스텀 예외를 반환한다.
- [x] **And** 검증에 성공하면 `Request` 객체에 테넌트 컨텍스트 정보를 주입한다.

### 시나리오 2: 이벤트 기반 감사 로그 적재 (Event-Driven Audit Logging) [Done ✅]
- [x] **Given** 계약서 생성이나 서명 완료 등의 도메인 이벤트가 발생한다.
- [x] **When** 비즈니스 로직(Service)에서 `EventEmitter2`를 통해 이벤트를 발행한다.
- [x] **Then** Audit 모듈의 이벤트 리스너가 이를 감지하고 AuditLog 엔티티(테넌트 ID, 유저 ID, 액션 타입 등)를 생성한다.
- [x] **And** 생성된 로그 객체를 데이터베이스에 안전하게 비동기로 저장한다.

### 시나리오 3: AI 계약 에이전트 연동 웹훅 (AI Agent Webhook for Notification) [Done ✅]
- [x] **Given** 외부 AI 엔진(모두싸인 캐비닛 등)이 알림 발송을 위해 웹훅 POST 요청을 전송한다.
- [x] **When** Notification 모듈의 엔드포인트가 요청을 수신한다.
- [x] **Then** 웹훅 페이로드를 파싱하여 대상 테넌트와 유저를 식별한다.
- [x] **And** 해당 대상에게 이메일 또는 슬랙 발송 로직(Mocking)을 호출하여 알림을 전달한다.
- [x] **And** 잘못된 페이로드 형식이면 적절한 예외 처리로 로깅하고 `400 Bad Request` 커스텀 예외를 반환한다.

## 4. 아키텍처 및 제약사항 노트 (Architecture Notes)
- **기술 스택:** Node.js, TypeScript, Nest.js, SQLite (Dev), TypeORM, Jest
- **테스트:** AuditService, AuthZ Guard, Notification 로직에 대한 Mocking 기반 Unit Test 작성 완료 (6 tests passed).
- **에러 핸들링:** Global Exception Filter 적용 완료 (`GlobalExceptionFilter`).
- **TypeORM 최적화:** AuditLog 엔티티에 `tenantId`와 `createdAt` 복합 인덱스 설정 완료.
- **서버 설정:** `main.ts`에서 CORS('http://localhost:3000') 및 0.0.0.0 바인딩 설정 완료.
